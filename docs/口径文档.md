# 收听数据日汇总 · 口径文档（S6-POD-040）

> 本文档与 `app/aggregate.py` 实现同义对应；期望值由独立实现 `tools/calc_expected.py`
> 逐条朴素手算（非主实现代码路径）生成，测试逐字段对账。

## 范围

每天 02:00（Asia/Shanghai）运行：`python -m app.aggregate`（无参数 = 汇总昨天）。
支持 `--from 2026-11-01 --to 2026-11-07` 回补任意日期区间（跨度 ≤92 天，to<from 拒绝）。

## 事件与归属

- 事件类型：`episode_view` / `play_start` / `progress` / `complete`。
- **stat_date** = 事件时间戳转 Asia/Shanghai 本地日期；跨午夜 session 的后续
  progress/complete 事件按各自时间戳归属（可能落入次日）。
- 听众标识：`user_id` 优先；为空用 `anon_id`。`episode_view` 不计入听众。

## 指标口径

| 指标 | 口径 |
|---|---|
| views | `episode_view` 事件数（不去重） |
| plays | `play_start` 按 `session_id` 去重 |
| unique_listeners | 有 play_start/progress/complete 的去重听众（user_id 优先，anon_id 兜底） |
| listen_seconds | `played_delta_sec` 之和（按事件 stat_date 归属） |
| completes | 有 `complete` 事件的去重听众数 |
| completion_rate | completes / unique_listeners；分母为 0 → NULL（不判 0） |
| avg_listen_ratio | listen_seconds / (unique_listeners × 节目时长秒)；节目时长缺失 → NULL；全站行不计算（无单一时长）恒 NULL |
| reach_10…reach_100 | 听众级最大进度（同一听众跨 progress 事件取最大值）≥ N% 的去重听众数；恰好 100% 计入 reach_100（+1e-9 容差）；全站行按「该日该听众跨节目最大进度」去重统计 |
| source_breakdown | JSON：`{"<source>": {"plays": 去重 session 数, "listeners": 去重听众数}}`；键取出现过任一事件的 source 并集，按 plays 降序；未知 source 原样保留 |

## 三层汇总

1. **episode_daily_stats**：每节目 × 每日一行；`episode_id='__ALL__'` 的行为全站
   汇总（plays/listeners/completes 跨节目去重重算，reach 按听众跨节目最大进度）。
2. **column_daily_stats**：栏目 × 每日一行，指标为栏目下各节目聚合（views/listen_seconds
   求和，plays/listeners/completes 跨节目去重；不计 avg_listen_ratio）。

## 幂等与事务

- 每个日期一个事务：先 `DELETE WHERE stat_date=day`（episode_daily_stats 与
  column_daily_stats）再重算插入；任一步失败整体回滚。
- 重复运行同一区间：行数与数值逐行不变（uuid 主键会更新，数值列完全一致）——
  测试以业务键排序取内容哈希比对。
